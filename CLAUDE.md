# Project: AI Build Night

This is an Effortless Rulebook (ERB) project. All development follows the effortless methodology.

## Layout

- `effortless-rulebook/` — the hub (`effortless-rulebook.json`), plus the rulebook editor (`edit-rulebook.sh`, `docker/`).
- `postgres/` — generated SQL substrate (`rulebook-to-postgres`). Never hand-edit.
- `app/` — the Expo (React Native) app, pinned to SDK 54. Consumes the generated API as its backend.
- `start.sh` — stop/restart entry point for the Expo dev server.

## CRITICAL RULES — Read Before Doing Anything
1. **`effortless-rulebook.json` is the Single Source of Truth.** It is the hub. LLM-direct edits are the default input spoke. Postgres and its generated SQL are *output spokes* regenerated by `effortless build`.
2. **NEVER edit generated files** — files 00-05 in `postgres/` are regenerated on every build.
3. **Always read from `vw_*` views**, never base tables. Always WRITE to base tables directly.
4. **Query the rulebook FIRST — NEVER read it directly.** `effortless-rulebook/effortless-rulebook.json` is the single source of truth but can be megabytes. A direct `Read` or `cat` of the whole file floods context and is never necessary. Use the derived ladder first (`minimize-rulebook` is installed):
   - `effortless-rulebook/effortless-rulebook.derived-read-me-1st.txt` — table/field names, read first
   - `effortless-rulebook/effortless-rulebook.derived-schema.min.json` — compact schema
   - `effortless-rulebook/effortless-rulebook.derived-schema.json` — full schema, no data
   - `effortless-rulebook/effortless-rulebook.derived-data.json` — data rows, on demand only
5. **Ask permission** before modifying the rulebook or running `effortless build`.
6. **Always run `effortless build`** after any change reaches the rulebook hub.
7. **Never reimplement business logic** in app code — consume calculated fields from views as opaque truth.
8. **NO MIGRATIONS on this project's local Postgres.** `init-db.sh` drops + recreates the DB on every build — there is no `migrations/` folder, no migrations tracking table, no incremental SQL deltas. Never run `ALTER TABLE` against the live DB. If the answer feels like "write a migration," the answer is **"edit the rulebook and rerun `effortless build`."**

## Editing the Hub
- **Rulebook-direct** (default): edit `effortless-rulebook/effortless-rulebook.json` (with permission), then `effortless build`.
- The **rulebook editor** (`effortless-rulebook/edit-rulebook.sh`) also lets you edit rows/schema through its API/admin UI — edits land in Postgres as uncommitted changes and can be saved back into the rulebook JSON via `POST /api/save-changes`.

## The Effortless Loop
CHANGE RULE (in `effortless-rulebook/effortless-rulebook.json`) → `effortless build` → CONSUME generated views/API in the app → repeat.
On "do a turn" / "rebuild", load **effortless-loop**.

## Build & Start
- Build: `effortless build` from project root (or `./start.sh build`)
- Start the app: `./start.sh` from project root
- Rulebook editor (DB + API + admin UI): `bash effortless-rulebook/edit-rulebook.sh`
  - API: `http://localhost:42441`
  - Admin UI: `http://localhost:42442`
  - Postgres: `postgresql://postgres:postgres@localhost:5442/effortless-rulebook`

## The app talks to the rulebook editor's API
The Expo app in `app/` is the frontend. Its backend is the generated API served
by the rulebook editor container (`http://localhost:42441`). Start with
`GET /api/docs` to discover routes, tables, and conventions before writing any
fetch code. Reads are snake_case; writes are PascalCase field names; calculated
fields (e.g. `Name`, `Kind`, `CountOfPros`) are read-only.

## ERB Skills
All conventions live in the effortless-* skills. Routing starts at **effortless-orchestrator**.
